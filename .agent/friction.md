# Журнал проблем и затруднений

## 2026-10-27 14:37 +03:00 — Сборка solution прерывается в параллельном режиме

- **Задача / контекст:** Проверка сборки после переноса приложения в `src/`.

- **Что произошло:** `dotnet build ... --no-restore` завершился сообщением MSB5021 о принудительном завершении `csc`, хотя ошибок компиляции не вывел.

- **Предпринятые попытки:** Повторная сборка с восстановлением пакетов и `-m:1`.

- **Решение:** Последовательная сборка завершилась успешно; причина первого прерывания не установлена.

- **Предполагаемая первопричина:** Возможная проблема параллельного запуска MSBuild в среде; подтверждений этому кроме единичного прерывания нет.

- **Предлагаемое улучшение:** При аналогичном сообщении повторить сборку с `-m:1` и проверить доступные ресурсы/состояние процессов.

## 2026-10-27 15:09 +03:00 — API Platform пришлось восстанавливать из сборки

- **Задача / контекст:** Заменить прямую интеграцию OpenTelemetry на `Texnokaktus.ProgOlymp.Platform`.

- **Что произошло:** В кешированном пакете Platform нет README и XML-документации, а nuspec не содержит URL исходников. Поиск версии через NuGet завершился отказом соединения с настроенным прокси `127.0.0.1:9`. Обычная reflection-загрузка методов также потребовала отсутствующие в контексте PowerShell зависимости.

- **Предпринятые попытки:** Изучены nuspec пакета и пример `UsePlatform()` в соседнем ResultService; затем метаданные и IL кешированной сборки прочитаны через уже установленный `Mono.Cecil`.

- **Решение:** Установлены API `ConfigureOpenTelemetry.WithTracerConfiguration`, обязательность `SERVICE_NAME` и встроенная настройка консольного Serilog. Использована кешированная версия `2026.9.19.2`; сборка solution прошла успешно.

- **Предполагаемая первопричина:** Пакет не поставляет документацию своего публичного API; ограниченная сеть затрудняет поиск дополнительных материалов.

- **Предлагаемое улучшение:** Добавить в пакет README, XML-документацию и ссылку на репозиторий с примером миграции, обязательными переменными окружения и перечнем настроек по умолчанию.

## 2026-10-27 15:46 +03:00 — Git submodule status не запускается в песочнице

- **Задача / контекст:** Определить ревизию и состояние submodule перед проверкой репозитория.

- **Что произошло:** `git submodule status` завершился ошибкой Git for Windows: `sh.exe` не смог создать signal pipe, Win32 error 5.

- **Предпринятые попытки:** Вместо команды submodule отдельно прочитаны gitlink в основном репозитории и HEAD и статус вложенного репозитория.

- **Решение:** `git ls-tree HEAD modules/Common.Contracts`, `git -C modules/Common.Contracts rev-parse HEAD` и `git -C modules/Common.Contracts status --short` позволили сравнить ревизии и проверить изменения.

- **Предполагаемая первопричина:** Вероятно, ограничение среды на создание IPC-объекта для Git Bash; точная причина не установлена.

- **Предлагаемое улучшение:** Проверить совместимость Git for Windows и ограничений песочницы; до исправления использовать отдельные read-only Git-команды.

## 2026-10-27 15:58 +03:00 — Валидаторы security-audit не запускаются через Windows Node.js

- **Задача / контекст:** Проверить обязательную карту покрытия полного security-аудита.

- **Что произошло:** `validate-coverage-ledger.cjs` в Windows Node.js завершился сообщением `OS no-follow and nonblocking input protection is unavailable`. Доступ к WSL из обычной песочницы также был запрещён.

- **Предпринятые попытки:** Проверены требования валидатора и локальные средства WSL; в Ubuntu команда `node` отсутствовала в PATH. Поиском обнаружен локальный Linux Node.js в каталоге VS Code Server.

- **Решение:** С разрешённым доступом запущен штатный валидатор через Linux Node.js в WSL; карта из 20 единиц прошла проверку.

- **Предполагаемая первопричина:** Валидатор требует `O_NOFOLLOW` и `O_NONBLOCK`, которые Windows-версия Node.js не предоставляет; настройка среды не предоставляет Linux Node.js в стандартном PATH.

- **Предлагаемое улучшение:** Документировать поддерживаемый способ запуска валидаторов на Windows и заранее проверять наличие безопасной Linux-среды с Node.js.

## 2026-10-27 19:23 +03:00 — Docker Engine недоступен для проверки сборки образа

- **Предполагаемая первопричина:** Вероятно, Docker Desktop или его Linux engine не запущен; состояние службы не проверялось.

- **Предлагаемое улучшение:** Для задач с Docker проверять доступность engine в начале работы и предусмотреть готовый локальный builder для проверки Dockerfile.

## 2026-10-27 19:24 +03:00 — Python в Windows указывает на заглушку Microsoft Store

- **Задача / контекст:** Проверить синтаксис GitHub Actions workflow с помощью YAML-парсера.

- **Что произошло:** Команда `python` в Windows завершилась сообщением о предложении установить Python из Microsoft Store.

- **Предпринятые попытки:** Проверены доступность YAML-модуля в Node.js и Python в Ubuntu WSL; локальный Node.js не содержал модуль `yaml`.

- **Решение:** Workflow разобран установленным в WSL Python 3 с PyYAML; для доступа к WSL потребовался выход из обычной песочницы.

- **Предполагаемая первопричина:** В Windows активен псевдоним Python для Microsoft Store, а доступного интерпретатора Python в PATH нет.

- **Предлагаемое улучшение:** Предоставить рабочий Python с YAML-парсером в среде Windows или документировать доступный путь через WSL.
